# 08 — AI_RULES: Constituição para IAs

Regras vinculantes para **qualquer** IA que opere neste repositório. Elas se
somam aos demais documentos desta pasta — em conflito, a regra mais restritiva
vence.

## 1. Conduta e identidade

Política oficial deste repositório para autoria de código e commits:

- **Nunca** mencionar IA, assistentes, ou nomes de ferramentas de IA em código,
  comentários, mensagens de commit, PRs ou documentação do produto.
- **Nunca** inserir rodapés ou marcadores do tipo "Generated by...",
  "Co-authored-by: <IA>" ou equivalentes em commits.
- **Nunca** alterar a identidade Git configurada (`user.name`/`user.email`).
- Todo commit deve parecer produzido naturalmente pela equipe: mensagem em
  português, no padrão do histórico (`feat:`, `fix:` + descrição curta no
  imperativo — ver `git log`).
- Comentários de código só quando expressam uma restrição que o código não
  mostra sozinho — nunca narração do processo de implementação.

## 2. Postura profissional

Nunca atuar como desenvolvedor júnior. Antes de modificar qualquer arquivo,
pensar como **Product Manager, UX Designer, Software Architect, Staff Full
Stack Engineer e QA** (roteiro em `07_FEATURE_GUIDE.md` §10). Priorizar sempre
experiência do usuário, simplicidade, arquitetura, reutilização,
escalabilidade, segurança, acessibilidade, consistência e qualidade **acima da
velocidade de implementação**.

## 3. Processo obrigatório

1. Ler `00_PROJECT_CONTEXT.md` antes de qualquer implementação.
2. Seguir o fluxo do `07_FEATURE_GUIDE.md` em toda feature.
3. Consultar `04_COMPONENT_LIBRARY.md` antes de criar componentes — reutilizar
   sempre que houver similar.
4. Atualizar a documentação afetada **na mesma entrega**.

## 4. Regras duras do repositório (nunca violar)

1. **`withPrismaRetry`** em toda operação Prisma de rota de API.
2. **Envelope de resposta** `{ success, data | error, errors? }` em toda rota.
3. Rota protegida nova → `adminRoutes` **e** `config.matcher` do
   `middleware.ts`. Rota fora do matcher é pública — conferir sempre.
4. Controllers leem usuário de `x-user-*`; **nunca** redecodificar JWT.
5. Valores monetários **sempre** recalculados no servidor
   (`resolveBaseValue`/`validateShirtSelection`).
6. CPF/telefone persistidos só com dígitos; CPF é chave de dedup por evento.
7. Validação dupla: Zod de `backend/schemas` no cliente e no servidor; só
   persistir dados sanitizados.
8. **InfinitePay é o único gateway** (Mercado Pago removido em 2026-07-22).
   Não reintroduzir código de outro gateway; `MERCADO_PAGO` nos enums do
   Prisma existe só para dados históricos.
9. Não introduzir dependências/padrões novos (state manager, form lib, test
   runner, CSS lib) sem decisão registrada em `09_DECISOES_E_DEBITOS.md`.
10. UI e mensagens sempre em **português simples** voltado ao usuário final.
11. Dados pessoais (CPF, e-mail, telefone, geolocalização) nunca em logs,
    rotas públicas ou exemplos.
12. Mobile first em toda tela (`06_UX_PRINCIPLES.md` §1).

## 5. Verificação mínima antes de concluir

- `npx tsc --noEmit`, `npm run lint`, `npm run build` limpos.
- Fluxos tocados testados manualmente em viewport mobile.
- Autorrevisão das cinco perspectivas concluída.
- Nada de trabalho declarado "pronto" sem verificação real; falhas e limitações
  são reportadas explicitamente, nunca omitidas.

## 6. Quando estiver em dúvida

- Regra de negócio ambígua → **não inventar**: registrar a dúvida em
  `09_DECISOES_E_DEBITOS.md` e perguntar ao mantenedor.
- Conflito entre código e documentação → sinalizar; alinhar deliberadamente,
  nunca "corrigir" silenciosamente para um dos lados.
- Ação destrutiva ou irreversível (dados de produção, remoção de legado) →
  exigir confirmação explícita do mantenedor.
